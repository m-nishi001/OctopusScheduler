# game-jackpot(ジャックポット)

会場の抽選演出。抽選ロジックと演出はブラウザ側(ホスト端末)で動き、サーバは景品・画面設定のレコードと、画像・BGM などの素材の保管だけを担う。

## 抽選 API(`DrawApplicationService`)

- `executeDraw({ memberRequestCount, prizeRequestCount })`
  - 1 回分の本抽選(メンバー → 確変判定 → 景品)を計算し、**結果を保存してから**返す。
  - 戻り値は `{ result, prizeRes, memberRes }`。`prizeRes` はアニメーション用の素材(`winnerPrizeId` / `dummyPrizeIds` / `isKakuhen` / `dummyWinnerPrizeId`)。
  - 当選済みのメンバー・景品は二度当たらない。メンバーか景品が尽きている場合は例外にする。
- `previewDraw(...)`
  - `executeDraw` と同じ計算をするが、一切保存しない(デモ・リハーサル用)。
- `getLastPrizeCount()`
  - `{ total, remaining }`。`remaining` が 0 になったら「おしまい」。

### 抽選の対象(`DrawPoolProvider`)

メンバー抽選の候補は、既定では名簿の全メンバー。外から絞り込めるよう、`DrawPoolProvider`(`getEligibleMemberIds(): Promise<string[] | null>`)という口を持つ。アプリのホストが `setDrawPoolProvider` で実装を渡す(例: ポータルから入室した人、またはイベントにエントリーした人だけ。参加者ポータルの `event-host.ts`)。

- `null` なら絞り込まない。配列なら、**候補にもリールのダミーにも、その中のメンバーだけ**を使う。名簿に無いIDは無視する。
- 対象が空、または対象の全員が当選済みなら `NoEligibleMembersError`(理由つきのメッセージ)で止める。
- 実装が例外を投げたら、そのまま抽選を失敗させる(**全メンバーにフォールバックしない**。対象外の人が当選する事故を防ぐため)。
- `previewDraw` も同じ対象を使う。

### 抽選の状態(`DrawStore`)

当選者・景品の在庫・確変の予定は、`DrawStore`(`control/draw/draw-store.ts`)が持つ。

- `SessionDrawStore`: セッションのホストとして接続しているとき。**セッションの結果ファイル(サーバー)が正本**で、同じセッションの中では、イベントを跨いでも同じ人・同じ景品は二度当たらない。リセットは管理画面の「結果をリセット」(`resetJackpot`)か、セッション/R2 のリセット。読み込んだ内容はメモリに持ち、通信は 画面を開いたとき・抽選の前・commit・reveal・予定の保存だけ(GAS は1回の通信が重い)。
- `RehearsalDrawStore`: セッションの外で動かしたとき、デモ(`?demo=1` / デモセッション)。メモリだけ(画面に「リハーサル（結果は保存されません）」と出る)。サーバーにも本番にも残らない。
- 抽選は「結果を確定(commit)→ 演出 → 当選者と景品が見えた時点で公開(reveal)」。確定できてから演出を始める。画面を開いたとき、確定済みで未公開の抽選があれば、引き直さずに同じ結果で演出し直す(`resumeDraw`)。

## 確変

- 景品には「確変対応あり」(`kakuhen`)のチェックがある。ONの景品だけが確変の回に当たり、フェイク演出(1枚目＝フェイク、2枚目＝本当の結果)に使われる。OFFの間は確変_抽選画像・確変_当選画像・確変_当選BGMは使えない(入力済みの値は消さずに残すが、抽選・演出では使わない)。この項目ができる前の景品(`kakuhen` が未設定)は、読み込み時に「確変_ の3つの素材のどれかがあればON」として補う(`normalizePrizeKakuhen`。保存済みのデータは書き換えない)。
- セッションで最初の抽選のときに一度だけ、確変対応ONで未当選の景品を取り置き、その数だけ確変の回を決めて、確変の予定(`plan`)として保存する(`calculateKakuhenTimings`。おまかせは全体の真ん中あたりに連続して置く。ONが 0 件なら確変なし)。「回を指定する」では、指定した回数がON景品の数と違うとき、本抽選画面設定に警告を出す。確変の回に当てるONの景品が尽きたら通常の演出で引き、通常の回でOFFの景品が尽きたら残りのON景品から引く(止まらない)。
- 取り置いた景品は通常抽選では引かれない(後の確変で重複当選しないため)。確変の回(「確定済みの件数 + 1」回目)に、取り置きの中から 1 件を選び、新しい drawId で確定する。サーバーも、確変の抽選に取り置き以外・通常の抽選に取り置きの景品が選ばれたら断る。
- UI は確変のとき、最終景品をルーレット上に 2 回(抽選画像・確変_抽選画像)並べ、2 回に分けて同じ景品へ止める(occurrence で別の扇に止める)。**景品の名前と ID は変わらず、変わるのはルーレットの扇と当選ダイアログの画像(抽選画像 → 確変_抽選画像)だけ**。確認用のデータ(`scripts/seed-content.js`)は、抽選画像と確変_抽選画像を別の画像にしてある。

### 次のサイクルの先読み(サイクル間のラグをなくす)

サイクルの切れ目(当選ダイアログ →「次へ」→ 次のメンバー抽選)で通信を待たせないよう、次のサイクルの材料を、いまの抽選の**公開(reveal)が済んだ時点から裏で**用意する。

- 用意するもの(`prepareNextCycle`): 終了の確認(景品・メンバーが尽きていれば「終了」を材料にする。終了の画面も同じ道で出る)→ 抽選 → 保存先への確定(commit)→ ルーレットの景品画像の下ごしらえ → メンバー抽選の写真の読み込み。画面の状態には触れない(見えている演出を壊さない)。
- 状態は `NextCycleSlot`(idle / preparing / ready / failed の純粋なモデル)、出どころは `CycleSource`。進行役(`DrawFlowController`)は `nextCycle()` を呼ぶだけで、用意済みなら通信せずにすぐ受け取る。用意中なら出来上がりを待つ(二重に抽選・確定しない)。
- 公開が済んでからでないのは、サーバーが「公開されていない抽選がある間は次の確定を断る」ため(この規則は変えない)。公開の通信中に押されたときは、公開(と先読みの開始)が済むのを待ってから受け取る(`HostPublisher.settled`)。
- 失敗しても退行しない: 先読みが失敗・矛盾(`JACKPOT_CONFLICT`)・無効化されたら、従来どおりその場で(保存先を読み直して)用意する。先読みが**確定した後**で使えなくなっても、確定済みで未公開の抽選として残るので、ホストの再読み込みと同じ道(`pending` → `resumeDraw`)で同じ当選者のまま演出し直せる。二重には確定しない。
- 取り消し: 抽選の失敗(読み直し)・公開時の矛盾(別の端末でのリセット)・保存先の切り替え・画面を離れるとき。用意済みのルーレットの画像 URL は破棄する。
- 割り切り: 先読みの時点で抽選の対象を決めるので、そのあとにエントリーした人は、その1回の抽選には入れない(次の回から入る)。先読みのあとに別の端末でリセットされた場合、その1回は記録に無い抽選を見せ、公開のところで矛盾として知らせて読み直す(演出の途中でリセットされたときと同じ扱い)。
- 通信の重複をなくす: 抽選の対象の一覧・メンバー名簿は1回の抽選につき1回だけ取得し、終了の判定と抽選で共有する(`drawNext`)。同じ抽選の公開が通信中なら重ねて送らない(`SessionDrawStore.reveal`)。メンバーの写真は並列(上限つき)に読み、抽選のたびに作り直す画面をまたいで共有の置き場(`MemberImageCache`)に残す。
- 操作の待ち: 進行操作のあとの待ち(`SETTLE_SEC`)は「演出が落ち着くまで操作を受け付けない時間」だけにし、通信は含めない。メンバー抽選の画面を出した後だけ、写真を先に読んである分 0.5 秒に短縮した。待ち方は `DrawContext.wait` で差し替えられる(テスト用)。

## 景品・画面設定・素材の保存

- 景品レコードの版は2。`migrateJackpotRecord` が、版2の段階で画面設定の項目を整理する(`demoSe1` を `demoDrawSe`(デモ抽選SE)に改名し、使っていない `demoSe2` / `resultSe1` / `resultSe2` を削除)。景品ランクは版1に満たないときだけ戻す。メンバーの拡張設定(当選しやすさ)は別の版(`MEMBER_EXTRA_SCHEMA_VERSION`)にして、景品の版の更新で戻らないようにしている。

- 景品と画面設定は **1件のレコード `{ prizes, screens, media }`** に入れる(`JackpotRepository`。端末は IndexedDB の `JackpotData`、サーバーは `jackpot-game/json/jackpot-config.json`)。旧形式は読まない(空として扱う)。
- 画像・音声は**素材の名前(ファイル名)**で参照する(`Prize.image` など、画面設定の `bgm` / `media` / `se` など)。同じ名前は同じ素材としてジャックポットの中で1つだけ持つ(縮小しない)。クイズなど他のモジュールとは共有しない。
- `media`(名前 → ハッシュ・MIME・サイズ)は状態として持たず、レコードを書くたびに、景品と画面設定が参照している名前から作り直す(`commit` が唯一の書き込み)。サーバーはレコードを書くとき、外れたハッシュのファイルを消し、参照先が無ければ断る。参照カウントも後始末も要らない。
- アセットタブは無い。景品・画面設定のフォームは共通の素材選択部品(`ui/components/media-picker.vue`。ファイルを選ぶ / 登録済みの素材から選ぶ / プレビュー / 外す)を使う。再生側は `JackpotRepository.blobOf(name)` で中身を引く。

### CSV の一括書き出し・取込(`@octopus/table-io`)

- 景品 `prizes.csv`: `ID, 名前*, 景品ランク(1〜5、標準3、5=豪華でレア), アニメーション(ルーレット|スロット), 確変対応(あり|なし), 抽選画像, 当選画像, 当選BGM, 確変_抽選画像, 確変_当選画像, 確変_当選BGM, 確変_ダミー当選景品ID`(内部の項目は `image, winningImage1, bgm1, image2, winningImage2, bgm2, kakuhenDummyPrizeId`)。確変_ダミー当選景品ID は、確変の回にダミー当選として先に見せる景品の ID(任意。空はいまのまま、`-` で外す。存在しない ID や自分自身は無視してランダム)。古い列名(画像1・BGM1 など)はエラー。確変対応は あり/なし だけ。置き換え(ファイルに無い景品を削除)を選べる。置き換えではファイルの行の順が並び順、追加・更新では既存の並びを保って新しい景品を末尾に足す。空のセルはいまのまま、素材のセルは `-` で外す。
- 画面設定 `screens.csv`: `画面*, 項目*, 素材, 文字, 種類, 効果, 秒数, 効果音, コンテンツ名`。画面は オープニング・説明・デモ抽選・本抽選・最終結果・エンディング、項目は画面ごとに BGM・抽選SE・メンバー抽選BGM・確変の回・停止秒数・参加者の停止(可/不可。空は可、それ以外はエラー)・コンテンツ。素材と効果音は素材フォルダか ZIP の `media/` から名前で探し、音と画像の取り違え・重複行・見つからない素材はエラー。取り込んだら開いている画面設定を読み直す(`screenTableIo`)。
- メンバー `jackpot-members.csv`: `ID*, 名前, 当選しやすさ(1〜10、標準5), 抽選対象(あり/なし)`。抽選対象はメンバーごとの明示フラグ(`JackpotMemberExtra.eligible`、既定 true。管理者かどうかとは無関係)で、空のセルはいまのまま。共通の名簿は消さないので置き換えは無い。名前は名簿の取込と同じ道(`rosterTableIo` の `table` に `jackpotMemberTable` を渡す)で名簿に書き、当選しやすさは名簿に書いたあと拡張設定へ1回で書く。名簿にいない ID は、名前があれば名簿に追加し、名前が無ければエラー。空のセルはいまのまま。古い CSV の「写真」「ランク」列は無視する。
- エラーの行が1つでもあれば取り込めない。取込は、素材を端末に入れてからレコードを1回だけ書く。

## 演出画面(`ui/pages/main-draw`)

- 進行は `ActionQueue` のステップ列。ホストの Enter か、管理端末の「次へ」で 1 ステップずつ進む。
- 共通テーマ(ラスベガス金×赤)は `ui/theme/jackpot-theme.css`、紙吹雪は `ui/components/jackpot-confetti.vue`。当選・おしまい・半分ダイアログ、結果画面、抽選の舞台はこれを使う。`prefers-reduced-motion` では動きを止める。
- 画像が無い賞品は、ルーレットの扇とダイアログに賞品名を表示する。

## テスト

- ユニット: `npm test -w @octopus/game-jackpot`。人数 × 景品数のマトリクス(`draw-full-run.spec.ts`)で、全員・全景品を引き切っても例外・重複が出ないことを確認している。
- 画面の通し: `npm run build && npm run e2e -- ui`(`e2e/ui/jackpot-*.spec.ts`)。
  - `jackpot-scale`: 規模別(1×1 〜 300×100、ルーレット/スロット)にホスト画面を最後まで進め、例外・はみ出し・賞品名表示・結果画面を確認する。`E2E_SHOTS=<dir>` を付けると各段階のスクリーンショットを保存する。
  - `jackpot-screens`: 全画面を開いて例外・横スクロールが無いことを確認する。
  - `jackpot-flow`: ホスト・管理・参加者の 3 端末での遠隔進行。

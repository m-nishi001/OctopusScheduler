# 認証と初回管理者

> **要点**
> - アプリは入口からログイン必須。公開はログイン画面だけ（名前を選ぶだけの匿名参加はない）
> - **同じURLから入り、アカウントの役割で画面が変わる**（管理者 → `/home`、参加者 → `/p`）
> - 参加者は **受付で自分専用のQRコードを読み取る**（またはID/パスワード）とログインできる
> - 最初の管理者は **ブートストラップ用パスワード**（シークレット）で作る。再ビルド・再デプロイは不要
> - 設定したら、ID `admin` とそのパスワードでログインするだけ
> - 全員ログインできなくなっても、シークレットを再設定すれば復旧できる

## 初回管理者を作る

| 環境 | 登録するもの |
| --- | --- |
| GAS | スクリプト プロパティ `OCTOPUS_BOOTSTRAP_ADMIN_PASSWORD` |
| Cloudflare | `npx wrangler secret put OCTOPUS_BOOTSTRAP_ADMIN_PASSWORD` |

1. パスワードを登録する（8 文字以上、推奨 16 文字以上）。ID を `admin` 以外にしたい場合は `OCTOPUS_BOOTSTRAP_ADMIN_ID` も登録する
2. ログイン画面で ID `admin`（または設定した ID）とそのパスワードを入力する。管理者アカウントが自動で作られる
3. 設定画面のアカウント画面で自分のパスワードを変更し、必要なら管理者を追加する
4. 手順 3 の後は、ブートストラップ用の設定を削除しておくのが望ましい

## 仕組みと安全性

| 項目 | 内容 |
| --- | --- |
| ブートストラップが有効な間 | ログインできる管理者（管理者権限＋パスワード設定済み）が **1 人もいない間だけ**。1 人でもログインできれば無効になるので、設定を残しても裏口にならない |
| シークレット未設定 | 何も起きない（誰も入れない） |
| セッション | ログイン後のトークンをブラウザ（localStorage）に保存し、以降はサーバーが毎回検証。有効期間 7 日 |
| 総当たり対策 | 同じ ID で 5 回連続失敗すると 15 分ロック（成功でリセット）。存在しない ID への試行は共通の上限で抑える |
| セッション掃除 | ログイン時に期限切れを削除。有効なセッションは最大 100 件で、超えると古い順に失効 |
| 投影用の実行画面 | `/execute/**` を開く端末も、一度ログインが必要 |
| 参加者アカウント | 管理者でないメンバー。ID/パスワード、または受付QRでログインし、`/p`（参加者ポータル）に入る。管理画面は開けず、管理者向けのAPIも呼べない |

アセット・JSON・ショートカットの読み取りも管理者限定です。参加者が使えるのは、セッション用の公開エンドポイントとメンバー名簿（id と名前のみ）だけです。

## 参加者の受付QR

会場が広くスクリーンが小さいと、イベント中にQRを読み取れない。そこで **受付で1回だけ、自分専用のQRコードを読み取ってログイン** してもらう。

**運用の流れ**

1. 設定画面 → アカウントで、参加者をメンバーとして登録しておく（パスワードは任意。QRだけでも入れる）
2. 「未発行の参加者に受付QRを発行」を押すと、全員分のQRコードが一覧で出る。「印刷」で名札などにする
3. 当日、受付で本人のQRを読み取る → 自動でログインし、参加者ポータル（`/p`）が開く
4. QRを忘れた人は、前日までにメール等で配ったID/パスワードでログインする

**仕組みと安全性**

| 項目 | 内容 |
| --- | --- |
| QRの中身 | `…/#/login?id=<ID>&key=<キー>`。キーはURLのフラグメント（`#`以降）なのでサーバーのログに残らず、ログイン画面が最初にURLから取り除く |
| キー | メンバーごとの約244ビットのランダム値。サーバーにはハッシュだけを保存し、平文は発行した直後の1回しか見られない（シートを閉じると表示できない） |
| 再発行・失効 | 再発行すると、配布済みのQRは使えなくなる。メンバーを削除するとキーも消える |
| 管理者 | 管理者にはキーを発行できない（印刷物のQRが管理者権限の入口になるのを避ける）。管理者になったメンバーの既存キーも使えない |
| QR画像の生成 | ブラウザ内だけで行い、外部のQR生成サービスにはURLを送らない（キーが漏れるため） |
| 総当たり対策 | キーは総当たりが成り立たない長さ。加えて、パスワードと同じID単位の失敗カウンタ（5回で15分ロック）を共有する |
| 限界 | 「他人のQRを読み取れば、その人としてログインできる」。厳密な本人確認ではなく、名前選択だけの参加よりなりすましにくい、という位置づけ |

IPごとのレート制限は、会場の共有IPから参加者が一斉にログインしても弾かれないよう緩めてある（[deploy-cloudflare.md](deploy-cloudflare.md#無差別アクセスへの備えレート制限)）。

## 復旧：全管理者がログインできなくなったら

管理者全員のパスワード情報を削除すると、ブートストラップが再び有効になります。パスワード情報のキーは `accounts-credential/<管理者ID>` です。

| 環境 | 削除方法 |
| --- | --- |
| GAS | スクリプト プロパティの同名キーを削除 |
| Cloudflare | `npx wrangler r2 object delete <バケット名>/__scalars__/accounts-credential/<管理者ID> --remote` |

その後、ブートストラップ用パスワードを（再）登録してログインします。

## ローカル開発で使う

ローカルの D1/R2 は worktree ごとに別なので、管理者とログイン済みセッションを投入するスクリプトがあります。`--local` 専用で、リモートには書き込みません。

```bash
npm run seed:local-admin -- --config <wrangler.toml> [--persist-to <dir>]
```

| 環境変数 | 既定 |
| --- | --- |
| `SEED_ADMIN_ID` | `admin` |
| `SEED_ADMIN_PASSWORD` | `local-dev-password` |
| `SEED_SESSION_TOKEN` | ランダム |

出力された `sessionToken` をブラウザの localStorage `octopus-session-token` に設定すると、ログイン済みで開けます。
